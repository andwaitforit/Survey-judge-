# DECISIONS.md

One short entry per non-obvious choice: date, decision, why, alternatives rejected.

- 2026-09-22 — Actions are keep/clarify/flag/replace, and we never terminate a respondent ourselves. Removing a real respondent is the expensive error; the customer owns that call.
- 2026-09-22 — Stylometric "AI-written" detection is logged as a weak signal only, never a deciding one. Accuracy collapses on edited text and it biases against non-native speakers.
- 2026-09-22 — Model access sits behind DecisionProvider so Jev can be swapped for a small LLM or an open clone. The vendor is not the moat; the decision log is.
- 2026-09-23 — `docs/TASKS.md` was missing, so the agent rebuilt M1–M8 from the other spec docs (see QUESTIONS.md). Stopping for the whole night was the alternative; the spec was detailed enough to proceed and mark the file as reconstructed.
- 2026-09-23 — Work is on branch `claude/policy-engine-milestones-1kbd4e`, not `feat/gate-core`. The session environment only allows pushes to that branch. Rename or merge it as needed.
- 2026-09-23 — Added dev dependency `tsx` to run TypeScript directly for `pnpm dev` and `pnpm eval`, with no build step. Rejected `ts-node` (slower, ESM friction) and a `tsc` build (extra step for the dev loop).
- 2026-09-23 — TypeScript is pinned to `~5.9`. TS 7 (native) is `latest` on npm, but typescript-eslint does not support it yet.
- 2026-09-23 — Check polarity: relevance/specificity/coherence/effort are *quality* scores (higher is better; a threshold trips when score < t). contradiction/gibberish/boilerplate/duplicate are *risk* scores (trip when score > t). This reads the PRODUCT.md example (`flag.relevance 0.30` is a floor, `flag.gibberish 0.70` a ceiling) literally. Both comparisons are strict, so a score on the threshold does not trip.
- 2026-09-23 — What counts as a "replace condition": a check that trips its replace threshold (`thresholds.replace.checks`, defaulting to the flag thresholds) with confidence strictly above `minConfidence`. At least `requireChecks` *distinct* checks must qualify. The schema puts a floor of 2 on `requireChecks`, so one check can never replace on its own.
- 2026-09-23 — Low confidence resolves toward keep through `confidenceFloors` (defaults: clarify 0.5, flag 0.6). A flag trip below the flag floor becomes a clarify trip; any trip below the clarify floor is ignored. A property test checks the result: lowering confidence never raises the action.
- 2026-09-23 — Re-score and budget behaviour: when clarify is not allowed (re-score, or session budget spent), a clarify-level outcome falls through to `keep`, as the rule order says. A re-score that meets replace conditions is capped at `flag` ("can only move to keep or flag").
- 2026-09-23 — AI authorship is kept out of the deciding path by construction. Config thresholds only accept the eight PRODUCT.md check names (strict Zod), so no such signal can trip an action.
- 2026-09-23 — Shadow mode returns `action: "keep"` and exposes `recommendedAction` separately (logged, and echoed in the response for the customer's own analysis). ARCHITECTURE.md's example response shows `action: "clarify"` with `mode: "shadow"`. CLAUDE.md rule 4 is explicit, so rule 4 wins.
- 2026-09-23 — Provider timeout contract: `scoreBatch` resolves with the checks that finished by `timeoutMs` and omits the rest (partial results). `runChecks()` adds a hard cut-off at `timeoutMs + 25ms`, validates every result with Zod, and drops malformed, duplicate or unrequested entries. It never throws. Zero results resolve to `keep` in the policy engine.
- 2026-09-23 — StubProvider scores with transparent text heuristics (filler list, keyboard-mash detection, question overlap, negation mismatch against prior answers, shingle Jaccard for duplicates). Confidence jitter is seeded from an FNV-1a hash of check + answer text. The heuristics are deliberately not tuned against the eval fixture, so the eval numbers are a floor. Mash detection skips non-Latin scripts rather than guessing.
- 2026-09-23 — **"Independent checks" for replace means distinct evidence families**: content (relevance, specificity, coherence, gibberish, effort), consistency (contradiction), duplicate, boilerplate. The first eval run showed that keyboard mash trips gibberish and relevance together at high confidence. Counting raw checks would have recommended `replace` for one junk answer. `requireChecks` now has a floor of 2 and a cap of 4 (the number of families). This is safer, since it resolves toward keep.
- 2026-09-23 — Eval scores the policy's `recommendedAction` in enforce mode (shadow would make everything keep). Each row is a fresh answer (not a re-score, no clarify budget used). Unless a row supplies `peerAnswers`, peers are other rows' answers to the same question (max 50), so duplicate detection works the way it would in production.
- 2026-09-23 — The eval "threshold" axis is a decision-confidence cut-off: interventions with confidence < t are dropped to keep. Each sweep row reports precision/recall/FPR (any intervention, and per action), coverage, and a calibration gap: the mean confidence minus the exact-action accuracy of the retained interventions. Overall calibration uses 5 reliability bins plus ECE. Correctness means an exact action match.
- 2026-09-23 — The bias guardrail compares *predicted* replace rates per group against the overall rate. The comparison is a strict `>` 1.5x (exactly 1.5x does not warn). Groups with n < 20 are marked "low n" but still warned on.
- 2026-09-23 — Two stub fixes made *after* seeing the first eval run (disclosed so the baseline is read correctly). (1) Filler non-answers ("good") now score gibberish 0.65, below keyboard mash; a filler answer is recoverable, which is what clarify is for. (2) Relevance no longer penalises short answers, because brevity is specificity's job. Both are principled, but they were prompted by the fixture. No further tuning was done.
- 2026-09-23 — `pnpm eval fixtures/labeled-sample.jsonl` resolves the path under `test/fixtures/` when it does not exist at the root. CLAUDE.md uses that path, and ARCHITECTURE.md puts fixtures in `test/fixtures/`.
- 2026-09-23 — Added `test/fixtures/study-config.recommended.json`. It is the PRODUCT.md example plus flag thresholds for `contradiction` (0.7) and `boilerplate` (0.8). The example config has no thresholds for those checks, so they can never act; the eval shows the cost of that.
- 2026-09-23 — The small-LLM provider targets the OpenAI-compatible `/chat/completions` API over built-in `fetch`, with no SDK dependency. That one interface covers Ollama, vLLM, llama.cpp server and most hosted gateways. It sends one short request per check, in parallel (temperature 0, max 40 tokens). The model returns `{score, confidence}`, and the parser tolerates code fences and extra text. Self-reported confidence is *not* calibrated; calibrate it against the decision log (e.g. isotonic) before enforcing.
- 2026-09-23 — Prompt-injection hygiene: answer text is sent inside `<answer>` tags, and the prompt says tag content is data. Prior answers go only to the contradiction check and peer answers only to the duplicate check, which minimises what each call sees. Every prompt says not to judge AI authorship and not to penalise non-native phrasing.
- 2026-09-23 — JevProvider sits behind an adapter marked `TODO(jev-api)`. The official docs (docs.typesafe.ai) and the mirror docs were blocked by the network egress proxy. The request/response shape follows third-party descriptions and is labelled unverified in code, in the fixtures, and in `modelVersion` ("(unverified adapter)"). There is no default endpoint, so it cannot be used without explicit configuration. It sends one request per check so that partial results work.
- 2026-09-23 — `test/setup.ts` replaces `globalThis.fetch` with a function that throws, so "no network in tests" is enforced rather than hoped for.
- 2026-09-23 — Prisma 7.10 (latest stable; npm `latest` is an 8.0 RC) with the `prisma-client` generator and the `@prisma/adapter-pg` driver adapter, which also pulls in `pg`. Prisma 7 needs a driver adapter, and it avoids the native query-engine download. The generated client lives in `src/generated/` (gitignored, rebuilt by `postinstall`). pnpm's ignored build scripts for `prisma`/`@prisma/engines` are left ignored; generate and migrate work without them.
- 2026-09-23 — Append-only is enforced in Postgres, not only in code. A `BEFORE UPDATE` trigger on "Decision" rejects every update except setting `finalOutcome` from NULL once. DELETE stays allowed for retention purges. `finalOutcome` stays a column, as the spec describes, rather than a separate outcome table.
- 2026-09-23 — Clarify budget and re-score state come from the decision log (count of `recommendedAction = clarify` in the session, and whether this question already got one). Nothing is stored in a separate session table. Counting *recommended* clarifies means shadow mode simulates the budget the way enforce mode would spend it.
- 2026-09-23 — `checks` jsonb stores only `{check: {score, confidence}}`. Triggers are not stored: the policy is deterministic, so they can be recomputed from the scores and `configVersion`.
- 2026-09-23 — Respondent `attributes` (language, region, age band) are accepted by the API, per the contract, but **not persisted**. CLAUDE.md says to stop and ask before storing personal data beyond the answer text. The bias guardrail runs on labelled eval sets for now (see QUESTIONS.md).
- 2026-09-23 — API keys are stored as sha256 hashes. The raw key is shown once by `pnpm db:seed`.
- 2026-09-23 — The Postgres store tests are opt-in (`pnpm test:pg` with `TEST_DATABASE_URL`), so `pnpm test` stays offline and database-free. They passed tonight against a local Postgres 16, including the trigger test.
- 2026-09-23 — Latency budget: `/v1/score` has a 450 ms total budget (50 ms under the 500 ms p95 target for network and serialisation). Store reads run in parallel and are capped at 60 ms each; the provider gets whatever remains minus 40 ms reserved for the policy and the log write. Measured tonight against the stub: p50 ≈ 3 ms (in-memory), about 20 ms end to end over HTTP against local Postgres.
- 2026-09-23 — Fail-open matrix: provider timeout or error → the missing checks cannot trigger, so it leans to keep. Config read fails → the default shadow config is used. Session read fails → the clarify budget is treated as spent (no clarify). Peer read fails → empty peer sample. Log write fails → the response is still returned and an error is logged. Any unexpected exception → `keep` with `degraded: true`. The response carries `degraded` so customers can see when the answer is keep-by-default.
- 2026-09-23 — A study with no stored config gets the default config (shadow + PRODUCT.md example thresholds) as `configVersion: 0`, so an integration works before anyone configures it. The config schema also *defaults* thresholds to those values. The smoke test showed that `PUT {"mode":"enforce"}` would otherwise have saved empty thresholds and silently never acted.
- 2026-09-23 — Added endpoints the spec implies but does not list. `PUT/GET /v1/studies/:studyId/config` is the only way to opt a study into enforce mode. `POST /v1/decisions/:id/outcome` writes `finalOutcome` once, returning 409 if it is already set. There is no UI (non-goal).
- 2026-09-23 — `sessionId`, `studyId` and `questionId` must match `^[A-Za-z0-9_\-:.]{1,128}$`, which also rejects emails. `attributes` accepts only languageGroup/region/ageBand, as short labels. Every body is strict: unknown fields are a 400 and are never stored.
- 2026-09-23 — The CSV export escapes cells by RFC 4180 and neutralises formula injection: a leading `= + - @` gets an apostrophe, because respondent text will be opened in Excel.
- 2026-09-23 — Batch scoring runs the items of one session in order (clarify state depends on earlier answers), with up to 8 sessions in parallel. Each item gets a 5 s budget. Every batch decision is logged like a live one.
- 2026-09-23 — `pnpm dev` without `DATABASE_URL` uses the in-memory store and prints a dev API key (or uses `DEV_API_KEY`). With `DATABASE_URL`, it uses Postgres (`pnpm db:migrate`, then `pnpm db:seed` to mint a key).
- 2026-09-24 — Vercel deploy fixes. (1) Vercel's Fastify preset only detects an entry file that imports `fastify` and calls `listen()`, so `src/server.ts` now creates the instance and `registerRoutes()` mounts the routes (`buildApp()` stays for tests). (2) Vercel type-checks with its own settings, where the global `Response` type lacks `ok`/`status`/`json`. `FetchLike` is now typed locally, and `defaultFetch` wraps the global. (3) `engines.node` is pinned to `22.x` (the CLAUDE.md stack) instead of `>=22`. Verified with `vercel build` locally, then by running the built function in both in-memory and Postgres modes.
- 2026-09-24 — Env vars are read through `readEnv()`, which treats empty or whitespace-only values as unset. The first Vercel preview crashed at boot with `unknown provider ""`: the project has `PROVIDER` saved with an empty value, and `?? 'stub'` let the empty string through.
